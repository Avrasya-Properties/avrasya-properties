# Backend audit and implemented controls
See [deployment/status](BACKEND_DEPLOYMENT.md) for the live activation blocker and first-admin setup.

The original website used static supplier JSON and a fictional localStorage CRM. The review branch adds Supabase Auth and protected staff membership; RLS-scoped contacts/leads/tasks/viewings/inquiries; shared CMS settings; published-only snapshots; safe supplier provenance; optimistic edits; guarded, atomic conversion/publication/deal operations; verified physical-unit links; Storage cover uploads; source review/CMS/staff/lease/maintenance management; append-only server audit events; persistent notification receipts and administrator application-data export.

The inspected project already contained 52 application tables, supplier imports and legacy SECURITY DEFINER RPCs without adequate internal authorization. Those legacy RPCs are revoked by the reviewed migration. Protected helpers live in the unexposed private schema with fixed search paths and explicit execution grants. Staff access also requires a live Auth session. Every application table has RLS; public writes go through a validated, rate-limited Edge Function and service-only RPC.

Limitations are explicit: the owner approved the reviewed migration after the initial automatic-review rejection; it and an index cleanup are now applied. First admin is deferred by the owner; exact allowed origins, hosted Auth/SMTP, Storage transfer verification and unattended reservation scheduling still require activation. The enquiry Edge Function is deployed but fails closed until the allowed origins are configured. Generic editors do not fabricate payment receipts, commissions or completed transactions. Payment rows are read-only. Production browser restore/reset is disabled.

CI uses isolated PostgreSQL and Supabase-compatible Auth helper definitions copied from the actual project. Browser persistence tests use real PostgREST/SQL authorization with fictional Auth endpoint fixtures. This verifies wiring and persistence without creating live users, sending mail or modifying imported client inventory.

Live post-migration checks confirm all 22 imported offers remain Draft; anonymous catalogue access returns zero offers and shared services/settings remain readable; anonymous CRM writes/reads and legacy RPC bypasses are denied; an authenticated session without membership sees no CRM. Security advisors report no WARN/ERROR findings. The rate-limit table intentionally has no client RLS policies. Redundant indexes introduced by the integration were removed, retaining original indexes and constraints. Informational foreign-key/unused-index findings remain for workload-based performance tuning.

Live read-only hosted checks passed against Supabase's actual Data API/Auth/Edge gateway: catalogue/settings/services are reachable; CRM and supplier payloads are denied; Auth is reachable; the deployed enquiry endpoint returns 503 until its allowed origins are configured. No live writes were performed.

Advisor references: [intentional no-client-policy rate-limit table](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy), [foreign-key index review](https://supabase.com/docs/guides/database/database-linter?lint=0001_unindexed_foreign_keys), [unused indexes](https://supabase.com/docs/guides/database/database-linter?lint=0005_unused_index). Informational findings do not justify adding every possible index or removing new constraint indexes before a workload exists.
